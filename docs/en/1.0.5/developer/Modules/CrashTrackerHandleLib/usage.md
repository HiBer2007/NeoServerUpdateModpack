# CrashTrackerHandleLib usage

## Quick start

```cpp
#include <crash_reporter.h>

int main(int argc, char* argv[])
{
    // 1) Install first: any later initialization crash is then covered
    HiBerCTM::InstallCrashHandler();          // empty argument = current exe directory
    HiBerCTM::InstallCrtReportHook();         // only effective in Debug builds
    HiBerCTM::SetCrashAppName("NSUM Editor");
    HiBerCTM::SetCrashHelpText(
        "  1. Check that workspace.json exists and is valid JSON.\n"
        "  2. Git operations require git.exe in PATH or install.conf.\n"
        "  3. Attach the whole crash-report/<timestamp>/ folder when reporting.");

    // 2) Add explanations per exception code (optional, stacks up)
    HiBerCTM::AddCrashTypeInfo("STACK_OVERFLOW",
        "Stack overflow: check for circular branch inheritance in the editor.");

    return runApplication(argc, argv);
}
```

## Public API

| API | Signature | Description |
|---|---|---|
| `InstallCrashHandler` | `void InstallCrashHandler(const std::string& dumpDir = "");` | sets the dump root directory (empty = exe directory), raises the stack guarantee via `SetThreadStackGuarantee` and installs the unhandled exception filter |
| `InstallCrtReportHook` | `void InstallCrtReportHook();` | installs the `_CrtSetReportHookW2` hook; only compiled in under `_DEBUG` |
| `SetCrashAppName` | `void SetCrashAppName(const std::string& name);` | application name, written to the first line of `.meta` |
| `SetCrashHelpText` | `void SetCrashHelpText(const std::string& text);` | troubleshooting advice, written into `.meta` |
| `AddCrashTypeInfo` | `void AddCrashTypeInfo(const std::string& name, const std::string& description);` | appends a crash type description block |
| `SetCrashCliMode` | `void SetCrashCliMode(bool enabled);` | `true` = after a crash run `CrashTracker --cli` and print to the current console (no window) |

Every declaration lives in `namespace HiBerCTM` (`include/crash_reporter.h`).

## Typical usage

### Console / CLI programs

```cpp
HiBerCTM::SetCrashCliMode(true);      // crash reports print straight to the current terminal
HiBerCTM::InstallCrashHandler();
```

In CLI mode the library runs `CrashTracker.exe --cli <dmp>` through an anonymous pipe and forwards the child output to the host's stdout/stderr - which avoids a GUI-subsystem EXE showing nothing at all when there is no console.

### Specifying the dump directory

```cpp
HiBerCTM::InstallCrashHandler("C:/Apps/NSUM/crash");   // reports go to C:/Apps/NSUM/crash/crash-report/<ts>/
```

Without an argument it uses the exe directory obtained from `GetModuleFileNameW`. Note that the **directory must be writable**; when installed under `Program Files`, point it explicitly at a user data directory.

### Diagnosing heap corruption (Debug only)

```cpp
#ifdef _DEBUG
HiBerCTM::InstallCrtReportHook();     // captures HEAP_CORRUPTION / _CrtIsValidHeapPointer
#endif
```

Debug-build CRT asserts never pass through `SetUnhandledExceptionFilter`, so this hook is the only way to catch them; when it fires it writes the same `.dmp/.trace/.meta/crash_signal.txt` layout and then terminates the process with `0xC0000374`.

### Crash artifact layout

```text
<exe directory>/crash-report/<YYYYMMDD_HHMMSS>/
├── crash_<YYYYMMDD_HHMMSS>.dmp     # MiniDumpNormal
├── crash_<YYYYMMDD_HHMMSS>.trace   # call stack text
├── crash_<YYYYMMDD_HHMMSS>.meta    # application name + help text + crash type descriptions
├── crash_signal.txt                # paths to the dmp and trace
└── crash_<YYYYMMDD_HHMMSS>_report.txt   # readable report generated by CrashTracker (only if opened)
```

## Notes

- **Must be called before any other initialization**: put `InstallCrashHandler` at the very top of `main`, otherwise early crashes (Qt plugin loading, configuration parsing) are not covered.
- **`CrashTracker.exe` must sit next to the host EXE**: the library looks for "current exe directory + `CrashTracker.exe`"; when it is missing the report is still written, but the analysis UI is not opened automatically.
- **The process is terminated right after the report is written**: the exception path uses `TerminateProcess` with the real exception code, the CRT hook path uses `0xC0000374`. This is by design; do not try to turn it into "keep running".
- **The CRT hook only covers Debug**: in Release `InstallCrtReportHook()` is a no-op, so `HEAP CORRUPTION`-class problems must be reproduced with a Debug build.
- **No heap allocation inside the hook**: the CRT path of `crash_reporter.cpp` uses stack buffers and Win32 APIs only. Do not add `std::string`/`new`/iostream to its callbacks - with a damaged heap that either crashes a second time or self-deadlocks.
- **`SetThreadStackGuarantee(64KB)`**: this keeps some stack available for the filter in stack-overflow scenarios, but extreme recursion can still prevent a report from being written.
- **Do not install it repeatedly**: once per process is enough; calling `SetUnhandledExceptionFilter` again displaces the previous filter (for example one installed by a third-party library).
- **`.meta` text is copied verbatim into the report**: English/ASCII is safer, because terminal code pages can render other scripts as garbage.
