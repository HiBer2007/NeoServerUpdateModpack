# 设计目标

## 目标

1. **服务器内容可审计**：所有文件在 Git 仓库中，变更可 review、可回滚；
2. **客户端一次配置、自动跟随**：玩家导入一次，之后每次启动自动同步；
3. **大文件不重复传输**：内容寻址 + 指针 + 缓存；
4. **分发体积小**：`.nsumpack` 默认只含清单；
5. **失败可见**：网络/校验/分支问题必须显式报错，不静默使用旧内容；
6. **不依赖系统环境**：内置 Git、内置运行时、可离线安装。

## 关键约束

| 约束 | 影响 |
|---|---|
| Windows 优先 | 路径/编码/进程创建需特殊处理（UTF-8 argv、`GetModuleFileNameW`） |
| HMCL 生态 | 通过 bridge 注入；需匹配 HMCL/FLF 版本 |
| Git 仓库是唯一来源 | 客户端不维护“服务器私有补丁”，补丁也进仓库 |
| 单机无服务端 | 无中心服务，metadata 只做版本发现 |
| 插件化 | 格式/解析/下载方式可扩展，不重新编译主程序 |

## 取舍

| 决策 | 选择 | 放弃 |
|---|---|---|
| 分发 | 清单型 `.nsumpack` + 仓库同步 | 整包下载（省流量，但依赖仓库可达） |
| 大文件 | 指针 + 内容寻址缓存 | 直接把 jar 放进包（简单，但体积大） |
| 同步 | 三层（L1/L2/L3）+ 策略 | 全量覆盖（简单，但会覆盖玩家设置） |
| 失败 | 中止启动 | 静默降级（玩家可能进错版本） |
| 插件 | C ABI 工厂 + 导出符号 | 语言无关进程隔离（复杂，但安全边界清晰） |

## 非目标

- 不做游戏内容分发平台（不托管 jar）；
- 不做服务端控制面板；
- 不替代 HMCL 的实例管理；
- 不保证跨大版本 HMCL 的二进制兼容（bridge 需匹配）。

## 可验证的目标

| 目标 | 验证方式 |
|---|---|
| 清单体积 | 无内嵌 `.nsumpack` ≈ 1 KB |
| 零信任 | 缓存命中仍重算 SHA-256 |
| 内置 Git | `info git` 显示 bundled |
| 失败可见 | 同步失败时启动中止且日志有错误 |
