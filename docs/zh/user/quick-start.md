# 快速开始

目标：导入服务器提供的 `.nsumpack`，完成首次同步并进入游戏。全程不需要手动下载模组。

## 前置条件

- 已安装 HMCL、FLFHMCL 与 nsum-bridge（见 [安装](./installation.md)）。

> **待补**：FLFHMCL 安装说明完成后在此补充链接。

- Runtime 已安装（HMCL → NSUM 页面应显示版本）。

## 第一步：导入整合包

1. 打开 HMCL →「安装整合包」/ 拖入 `.nsumpack`；
2. 类型会被识别为 **NSUM 整合包**；
3. 选择安装位置（实例名可自定义），确认。

bridge 会：

- 创建实例目录；
- 写入 `<实例>/.NSUM/instance.json`（仓库地址、整合包分支、Git 分支、游戏/加载器版本等）；
- 若安装包带显式内嵌文件，按清单 `embedded[]` 安装并写入 SHA-256 缓存。

## 第二步：选择分支（首次启动/首次同步）

启动实例时，bridge 会在**任务对话框内**依次让你选择：

1. **Git 分支**（仓库代码分支，例如 `main`）；
2. **整合包分支**（内容分支，例如 `base`、`client`）；
3. 确认。

只有单个候选时会自动跳过对应步骤。选择结果会写入实例标记，后续启动沿用，可在实例设置里重选。

## 第三步：首次同步

确认后 Runtime 开始同步：

```text
克隆/更新仓库 → checkout 分支 → 合并整合包分支 → 解析指针下载 → 同步配置/模组 → 完成
```

首次同步需要下载模组，耗时取决于网络与体积；进度显示在 HMCL 任务对话框。

## 第四步：启动游戏

同步成功后：

- 对应游戏版本与加载器会自动安装/切换（NeoForge/Fabric 等）；
- HMCL 继续正常启动流程，进入游戏。

之后每次启动都会先检查并同步差异，只有变化时才下载。

## 验证

| 检查项 | 预期 |
|---|---|
| 实例目录存在 `.NSUM/instance.json` | 是 |
| `.hmcl/nsum/logs/` 有同步日志 | 是 |
| 游戏版本/加载器与服务器要求一致 | 是 |
| 模组数量与服务器一致 | 是 |

## 出问题怎么办

- 同步失败：查看 `.hmcl/nsum/logs/` 最后一份日志，对照 [故障排查](./troubleshooting.md)；
- 分支选错：重新启动实例，在分支选择对话框改选；
- 游戏启动崩溃：先确认同步成功，再检查是否缺少前置模组/Java 版本不符。
