# ADR 0002 · 三层同步体系（L1/L2/L3）

## 状态

已接受（2026-08-05 实施；2026-11-03 语义纠正：`save/` 字面路径不拷贝、交由 L3 路由）

## 背景

NSUM 把仓库内容同步进玩家实例目录，但目标目录不是空的：玩家有自己的模组、资源包、存档，HMCL 也在此写入 `modpack.cfg`、`hmclversion.cfg`、`log4j2.xml` 等运行文件。同步必须同时满足互相冲突的诉求：

- 服务器更新配置或换模组后，客户端要拿到新内容；
- 服务器删掉的文件，客户端也要删掉，否则旧模组继续生效；
- 玩家自己加的东西不能被误删，存档里的世界配置要按服务器规则逐存档下发；
- 同一套规则要能表达「这个文件夹严格镜像」「这个配置文件只合并某几个键」。

一刀切「全量覆盖」会删玩家数据；一刀切「只增不删」则永远删不掉服务器已移除的文件。因此需要分层表达不同粒度的意图。

## 决策

采用三层规则，粒度从粗到细，优先级从低到高：

**L1 文件夹策略**（`sync_policies.folders`，最长前缀匹配、递归子目录）

| 策略 | 行为 |
|---|---|
| `skip` | 完全不碰 |
| `mirror` | 覆盖写入并删除目标多余项（严格镜像） |
| `incremental_add` | 只补缺失，已存在不动 |
| `incremental_overwrite` | 保留多余项，同名文件覆盖 |
| `default` | 兜底值；未配置时实际按 `incremental_add` 处理 |

**L2 文件特化**（`sync_policies.files`，精确路径或尾部 `*` 前缀匹配）

| 模式 | 行为 |
|---|---|
| `force` | 无条件覆盖，忽略所属文件夹策略 |
| `full` | 覆盖，但仍遵守文件夹策略（等价「无文件策略」） |
| `partial` | 按 `tracked_keys` 交给对应解析器插件做半同步 merge，未跟踪的本地键保留 |
| `ignore` | 不碰 |

**L3 存档 serverconfig**（仓库内 `save/[save]/serverconfig/`）

- `[save]` 是字面占位目录：仓库里只维护一份规则与内容，同步时对目标 `saves/*/serverconfig/` 的**每个存档**执行。
- 规则文件：`.rule/globle.json`（未单列文件的默认模式）与 `.rule/list.json`（逐文件 `{mode, tracked_keys}`）。
- 模式与 L2 统一为 `full` / `force` / `partial` / `ignore`；`partial` 无解析器时回退整文件覆盖并告警。
- `.rule/` 与仓库内 `save/**` 不做字面拷贝，避免把规则写进玩家存档目录。

配套约束：

- `default_folder_policy=mirror` 时，未显式列出的根目录也参与严格镜像，但排除 `saves/`、显式策略路径、根级 `<id>.json`/`icon.*` 与受保护的 HMCL 运行文件（`log4j2.xml`、`options.txt`、`natives*`、根级 `*.jar`、`modpack.cfg`、`hmclversion.cfg`）。
- `.NSUM/hashes.json` 记录「上次同步写入」的文件，只有被记录过、且本次构建不再产出的文件才算「仓库已移除」，可以删除；玩家自放文件永不被判为多余。
- `mods` 作用域的镜像额外处理 `.jar.disabled` 清除与自定义模组收获到 `.NSUM/custom/mod`。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 全量覆盖（清空重写） | 实现最简单、结果最确定 | 删玩家数据与存档配置，不可接受 |
| 只增不删 | 安全 | 服务器移除的模组永远留在客户端，版本漂移 |
| 仅按文件清单逐条规则 | 粒度最细 | 配置成本高、无法表达「整个目录镜像」 |
| 三层策略（本决策） | 粗粒度默认 + 细粒度例外，可解释 | 规则组合有学习成本，需要预览工具 |

## 后果

- 正面：默认策略一次配置覆盖大多数目录；服务器删除可生效；玩家数据与存档受保护；同一套规则被 CLI、GUI、bridge 共用。
- 负面：规则匹配顺序（最长前缀、文件优先于文件夹）必须被文档化，否则容易出现「以为会覆盖却没覆盖」；`partial` 依赖解析器插件，缺插件时语义降级。
- 影响范围：`NeoWorkspace`（策略模型与合并）、`NeoBuild`（`SyncPolicyExecutor`、`ServerConfigSync`、预览 U/M/D）、编辑器规则编辑器、bridge 启动同步、端到端 fixture 的 C/D/E 组。
